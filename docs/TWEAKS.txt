# Tweaks Reference

Every tweak StreamReady can apply: what it actually changes, how risky it is, and how the undo works. Risk levels:

- **Low**: safe for almost anyone, easily reversible, no real downside.
- **Medium**: reversible and generally safe, but has a real tradeoff (needs a reboot, affects a specific feature you might rely on, etc.) worth understanding before applying.
- **High**: a genuine security or stability tradeoff. Never ticked by a goal. The Gaming and Streaming presets list one Advanced item (Keep core Windows in memory), which starts switched on in the preview and still needs the "I understand" tick in the review list; the other High items are in no preset, and you have to find and select them deliberately. (The "Select all" button on the Pro > Everything page is the exception: it ticks every setting that fits your PC, including these, unless Safe Mode is on, so review the list before you Apply.)

All tweaks below save your PC's actual prior setting before changing anything. How exactly each one can be put back (Exact, Partly, Manual or Cannot be undone) is listed in "What Undo covers and what it cannot" near the end of this file.

A System Restore point is tried before each batch of changes. It can fail (for example if System Restore is turned off), and it is a last resort: Undo uses the saved originals (see the main README).

## Risk badges in the app (Safe / Careful / Advanced)

The new interface shows a badge on every setting. It is separate from the Low / Medium / High wording below and is stricter, because it decides what a goal may tick for you.

- **Safe** (13 settings): registry-only, Undo restores your exact original state (including "this value did not exist"), no service, driver or security loss, and the visible effect is small. Goals tick only these. They are: Game Mode; Faster windowed games; Variable refresh rate; Fullscreen tweak (disable fullscreen optimizations); Turn off Game Bar recording; Advertising ID off; Activity history off; PowerShell 7 telemetry opt-out; Block suggested apps; Stop update sharing (two settings); Stop cross-device sync; No surprise restarts after updates.
- **Careful**: reversible, but it changes how Windows looks or behaves in a way you would notice, or touches services, drivers, power or USB. Never ticked for you; you can add related ones with one optional button.
- **Advanced**: can affect stability or security. Needs an extra "I understand" tick in the review list.

Undo: before changing anything, the app saves the original state of what it is about to change (for registry tweaks: whether each key and value existed and what it held) in the protected folder `C:\ProgramData\StreamReady-OSS\undo`, and Undo restores exactly that, also after you close the app or restart Windows. Other kinds of settings (services, power plans, adapters, Windows features, scheduled tasks, files) use the same engine with their own saved originals. What it covers and what it cannot is listed in **What Undo covers and what it cannot** near the end of this file.

## Timer Resolution

Forces Windows' global timer resolution to 0.5ms for lower input latency, via a small resident helper process (registered to start at logon, since the effect only lasts as long as the calling process is alive).

**Risk: Medium-High.** This is a well-known tradeoff in the enthusiast community: higher timer resolution system-wide can increase power draw and affect battery life/thermals on laptops, continuously, independent of whether a game is actually running. Undo stops the helper process immediately and unregisters the startup task. The helper script is kept in the protected `C:\ProgramData\StreamReady-OSS` folder, and the task starts PowerShell without loading a user profile.

## What Undo covers and what it cannot (every setting)

Both editions of StreamReady use the same Undo engine. Before a setting is changed, the app saves its original state in a protected folder (C:\ProgramData\StreamReady-OSS\undo, next to the folder the paid edition uses but never shared with it), so Undo keeps working after you close the app or restart Windows. "Undo Last Batch", the Undo buttons on the results page and the Undo buttons under History and Undo all use these saved originals. If StreamReady cannot save the original of a setting exactly, it does not change that setting and says so.

How to read the grades below:

- **Exact**: the bounded setting the tweak changes is saved and put back, and the result is read back and checked. This was tested with fixtures and mocks and on one test PC, not in a lab on every kind of hardware.
- **Partly (non-exact)**: the main setting is put back, but something around it is not (a restart is needed, a program has to be reopened, a download stays installed, or only a subset is covered). The note says what to check.
- **Manual**: the app cannot do it by itself. It keeps the item in History with the steps until you press "I did these steps". It never says "put back" for a manual item.
- **Cannot be undone**: deleted or transient data and external repairs. The limit is stated before the action starts and you are asked to confirm.

Rules that apply to everything:

- Two changes on the same setting are undone newest first. If you undo the older one first, StreamReady names the newer one and offers to undo both in the right order.
- A saved original belongs to the Windows account that made it. Another account cannot restore it, and an old record that is not tied to an account is kept for you to review, not guessed.
- If the list of saved originals is damaged, or its folder is not safe, StreamReady stops and says so instead of making changes it could not undo. History offers "Start a new undo list" (the damaged file is kept).
- If an adapter is unplugged when you press Undo for DNS, its saved original is kept: reconnect it and press Undo again, or choose "Give up on this".
- A saved original that this version cannot use is kept and shown in History with a button to discard it (a copy is kept). Applying that setting again is blocked until you decide.
- A program that a tool installed is removed by Undo only when the install can be proven to be this tool's own. Otherwise Undo gives you the steps to remove it yourself.
- The restore point is separate and is never deleted by Undo.

### What has and has not been tested

The saved-original engine, every kind of setting it covers and the History page were tested with automated suites (fixtures, mocks and throwaway registry keys) and with the app's own self-test, and the window was run on one Windows 11 PC. They were NOT tested in a lab on every kind of hardware: real winget installs and uninstalls, real unplugged adapters, real boot entry changes, real NVIDIA and AMD drivers, a Windows account joined to a work or school directory, and a stored sign-in password were all checked with mocks only. If something is important to you, create your own restore point first.

## The protected folder

Anything StreamReady later runs with administrator rights (the two downloaded tools and the helper script that the scheduled task starts) is kept in `C:\ProgramData\StreamReady-OSS`. That folder is owned by Administrators, Administrators and SYSTEM have full control, and ordinary users can only read it. This matters because a normal program running under your own account could otherwise replace a file that StreamReady is about to run as administrator.

Before every use the folder and everything in it is checked. If it contains a link, a file owned by anyone else, or anything another account can modify, the whole folder is deleted and rebuilt. If it cannot be created and confirmed safe, the tweak stops instead of falling back to an unprotected location. The folder name is different from the commercial edition's, so the two never touch each other's files.

The saved originals for Undo are kept below the same folder (`undo` and `undo-files`). They are checked the same way before they are read or used. A folder that holds saved originals is never deleted or rebuilt automatically: if its permissions are wrong, StreamReady stops and tells you instead of using it. The paid edition keeps its records in `C:\ProgramData\StreamReady`, so the two editions never share or restore each other's records.

## About the download-verification approach (hashes and signatures)

Two items download and run an executable instead of just changing settings. (The Downloads area is different: it installs well-known tools through `winget`, the Windows package manager, with no bespoke download handling.)

- **HIDUSBF** (USB polling rate tool): pinned to one exact file at one exact GitHub commit, verified against a SHA256 hash written in the script (search `src/StreamReady.ps1` for `expectedSha256`) before anything is extracted or run. If the hash does not match, the log says so and it refuses to run it. The download cannot be undone (the tool file stays; see the grades table).
- **Nvidia Profile Inspector**: always fetches whatever the upstream project's "latest" GitHub release is (so a fixed hash is not possible); it relies on its digital signature instead. It is only used by the NVIDIA game profile tweak, which is switched off in this build until its Undo has been verified on real NVIDIA hardware. The download code is kept for when that tweak is switched on again.

For both, the download is unpacked in a staging folder inside the protected folder and checked there first. The signature check works like this: a valid digital signature is accepted; an unsigned file shows an explicit "this is not verified, run it anyway?" prompt; any other result (tampered, untrusted, or could not be checked) is refused outright. Only a file that passed is moved into the tool cache, and the staging folder is always deleted afterwards.

When a tool is approved, its SHA256 is recorded inside the protected folder (these are the hashes of the downloaded tools, not of StreamReady itself; how to check StreamReady's own hashes is in the README). On later runs the cached copy is used only if it still matches that record and its signature has not broken; otherwise the cache is cleared and the tool is downloaded again. You are not asked the same question twice for an unchanged file. A valid signature proves the file is intact and signed by someone, not who the publisher is, so check the source yourself if that matters to you.
